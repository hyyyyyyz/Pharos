## 三处比它们的体量更重要

### 一、用户会被卡在一个无法恢复的状态，而界面给的是错误指引

每日文摘的总开关在网页版手里。桌面版**任何地方都没有这个控件**——而它自己的「已关闭」
空状态会把用户送到偏好设置面板，并写着"在「设置 → 每日论文」中重新开启即可"。

于是一个只用桌面版的用户，在这个状态下**被卡住，并且被给了一条无法执行的指引**。

补控件时差点犯第二个错：`pharos-prefs-daily-enabled` 这个 id **已经存在**，是单个研究
方向的状态标签（「启用中」）。复用它会让复选框显示错误文字，覆盖它会弄坏原来的消费者。
是**跨语言一致性脚本**发现的——一次本该新增两个 id 的编辑之后，它报告 id 总数没变。

### 二、"整套界面消失"写了三遍，代码没做

翻译关闭时，`_applies()` 检查条目、凭据、附件，**唯独不检查账号开关**。于是章节把标题
画出来，`render()` 再拒绝填内容。

**一个空章节不是"这套东西不在了"，它就是这套东西，坏了。** 而这个意图在三处写着，
包括一个测试。

### 三、溯源藏在 tooltip 里等于没有

「哪个模型写了这些解读」只存在于两个 tooltip 中。这一屏上每一条中文速览、每一个评分都是
那个模型的产出。**没人会去悬停的溯源，就是没有溯源。** 现在是工具栏上的一个 chip。

## 一条我一路说错的基线

整个会话里我反复引用"上游 `itemPane` + `zoteroPane` 稳定在 199/203，四个已知失败"。

**这句话是不准确的。** 那两个套件实际得分在 **189–199** 之间波动：四个失败是硬的、可复现的
（bibliography-entry 模式，`不详` vs `n.d.`），其余是窗口未处于系统激活态时超时的焦点测试，
**在完全相同的代码上，超时的个数每次都不一样**。

把区间上沿当成基线，会让比对在两个方向上都不可靠——**运气好的一次掩盖回归，运气差的一次
凭空造出回归**。

所以这一轮改用三对三测量：带本轮改动 196 / 190 / 192 / 192，不带 192 / 191 / 191。
同一区间，无回归。更早对条目树列做的 A/B 里，**不带改动的那一侧反而更低**（189 vs 196）——
那正是信号被噪声淹没时的样子。

已写进 AGENTS.md，并写明判断回归要三对三跑，不能信单次。

## 为什么这一轮要问「刻意的差异有没有写下来」

前两轮里，「文献探索不轮询」被当成缺口报了**两次**。它是刻意的，理由也成立
（`POST /discovery/search` 是同步的，持久化的 `running` 意味着请求中断而非进行中），
但那个理由当时只存在于代码注释里。

**一个刻意的差异如果没有写下理由，它在记录上就是缺口**——下一次比对会把它当 bug 再报一遍，
而重复推导同一个答案的成本，比写下来一次高。

所以这一轮明确要求逐条说明理由是否已落到文档。结果：11 条已有记录（`DECISIONS.md` §12、
模块头注释、代码注释），1 条只是隐含的（日期格式），已一并处理——顺带发现桌面版
**两个窗口的日期格式互不相同**：一个用应用语言、一个用系统语言，zh-CN 构建在 en-US 机器上
会把自己的标签画成中文、日期画成英文。

## 结论

**界面复刻这个目标已经达成。** 终局比对列出的 10 处差异全部关闭，11 处刻意差异全部有据可查。

现状：

- 桌面 Pharos 测试 **565 个全部通过**（第一轮结束 414，第二轮 563）
- 两个语言文件 **678 个 id 完全一致**
- 网页版 **39 个测试**（本轮之前这个项目没有测试运行器）
- 后端 **936 passed**
- 完整上游套件 **3364/3404**，40 个既有失败已逐类归因，并 A/B 确认与本项目无关

### 仍然存在的差异，以及为什么可以接受

- **11 处刻意的产品差异**，每一条的理由都在仓库里。它们不是缺口：桌面版是一个文献管理器，
  网页版是一个浏览器里的写作与管理面。硬要在这些点上一致，会让两边都更差
- **桌面版在 10 处反超网页版**（摘要有独立标题、分析模型是可见 chip、规则模式带可见警告块、
  每篇论文的解读状态按 id 隔离、轮询有上限等）。这些不是"网页版的缺口"，是桌面版走得更远的
  地方，已记录供网页版后续参考

### 不属于界面复刻的独立议题

**Zotero 8.0.5 基线对齐**：客户端源码 schema 129，在售 Zotero 是 123。它阻塞的是将来的
共享文库方向，**不影响当前隔离库的使用，也与界面无关**。计划见
[CLIENT_DATA_ARCHITECTURE.md](CLIENT_DATA_ARCHITECTURE.md)，路线图第 1 项。

**上游套件的不稳定性**：189–199 的波动是这台机器与上游测试的性质，不是本项目引入的。
`syncLocalTest` 还会弹出一个无人接管的模态框，**完整套件无法无人值守运行**——已写进
AGENTS.md，免得下一个人在 30 分钟的运行中途才发现。
