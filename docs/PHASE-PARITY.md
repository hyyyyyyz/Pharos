# 阶段记录：界面复刻

目标是让桌面客户端**完全复刻网页版的界面与结构**。做法是先把两边逐模块比对出缺口，
再按缺口施工，最后对成品做对抗性复查。

前序阶段见 [PHASE-CLIENT.md](PHASE-CLIENT.md) 与 [PHASE-EVIDENCE.md](PHASE-EVIDENCE.md)，
关键决定见 [DECISIONS.md](DECISIONS.md)，改 Zotero 时会静默出错的坑见
[`../client/BRANDING.md`](../client/BRANDING.md)。

---

## 比对结果：模块清单是齐的，模块内部不是

五个模块（文库／每日论文／文献探索／研究项目／管理后台）在两边一一对应，顺序和图标
逻辑也一致。缺口全在模块内部：

| 模块 | 比对前的实际完成度 |
| --- | --- |
| 每日论文 | 约 **15%**。右侧详情面板整个不存在——中文速览、四类要点、五项评分、信息栏、英文摘要全部抓下来就丢弃 |
| 文献探索 | 分析模式（规则 vs AI）**完全不显示**。规则抽出的英文原句和 AI 中文解读渲染在同一个框、同一种样式里 |
| 研究项目 | 8 个写操作里桌面版有 1 个。九阶段时间轴不存在，推进后无法回退 |
| 阅读面 | AI 对话**复用已有会话但从不加载历史**，模型带着用户看不见的上下文回答 |

## 反复出现的三种错误

比对和复查加起来定位了六十余处问题。抽掉细节，它们其实是同三件事。

### 一、缺省值倾向于说好听的那个

研究项目的分析模式判断**fail-open**：`analysis_mode` 缺失时渲染成「有模型解读」且不挂
任何标记。数据少一个字段，界面就替它编了一个更体面的答案。

同类的还有：文献探索里精读**故意不覆盖「局限」**（后端如此设计），但卡片此时已挂上
「AI 中文解读」标记，那一行仍是从英文摘要按线索抄出的原句——它还是四行里唯一的英文，
读起来像翻译漏了，实际是来源不同。

修法统一：缺失即按规则处理，且每一处来源不同的内容自己带标签。

### 二、界面知道的事，产物不知道

每日论文把模型的解读作为**子笔记**挂在带 PDF 的 preprint 下——Zotero 惯例里那是用户
自己写的位置。而模型**只看了摘要**（后端 `reader.py` 明写「The model reads this and
nothing else」），所以「方法」「结果」两条是推断不是阅读。半年后没人分得清它和自己的
读书笔记，它会被当作自己的理解引用出去。

文献探索同理：卡片上显示着模型名，存进文库的笔记里一个字都没有。

修法：三处笔记都带溯源行，写明是模型生成、是哪个模型、模型只拿到了什么。并且钉了测试。

### 三、失败不出声

- `Zotero.getString(id, 参数)` 会路由到 `.properties` bundle，**en-US 下直接抛异常**。
  它出现在四个窗口里，其中 `translate.js` 那处在轮询循环里——en-US 用户在第一个进度
  回调就丢掉正在付费进行的翻译，而任务还在服务端跑。讽刺的是 `pharosAdmin.js` 早就有
  正确的 helper，**注释里写着的正是这个 bug**，只是另外几个窗口写的时候没用它。
- `_signedOut` 是单向 latch，而模块文档只加载一次（rail 只切 `hidden`）。登录前打开过
  每日论文的用户，登录后模块**永远是死的**，只能重启应用。
- `/dates` 请求失败会清空已经加载好的当天列表，并打印「请确认服务已启动」——而服务刚
  应答过。更糟的是成功解读一篇后会重载日期，所以一次抖动就能把用户刚花钱得到的结果
  换成错误页。

## 有代价的判断

**修改了一条已记录的决定。** DECISIONS §4「读在客户端、写在网页端」被理解得过宽，
导致桌面研究项目模块只读：研究者能看见九个阶段却只能往前走，改不了任何一条记录，
空状态还叫他去开浏览器。**看着论文改假设，本身就是读这一侧的事。** 已在 §4 留下修订
记录而非悄悄改掉。副作用值得一提：桌面版 `create`、`getArtifacts` 早就写好了，
**从来没有任何界面调用过**——完成的工作因为一条记录在案的决定而没能到达任何人。

**删掉了一个样式表。** `scss/pharosDaily.scss` 在三个窗口各自拆出样式表后，没有任何
文档链接它，六个类名逐个查过也无人使用。同时发现 `npm run build` **不会删除已删源文件
的构建产物**——一个链接着已删样式表的文档会在开发树里照常工作、在发布版里挂掉。

**一条发现被驳回了。** 详情面板每次轮询重建会重置滚动位置——这条经查不成立：
`replaceChildren()` 和随后的 `append()` 在同一次同步调用里完成，没有任何布局刷新观察到
空盒子。按这个理论写的保存／恢复代码被删掉了，而不是留着当"已修复"。但调查反而找到了
反向的真 bug：**正因为偏移量会保留**，切换到另一篇论文时会停在上一篇的滚动位置。

**「部分完成」不能只靠颜色区分。** 文献探索的检索历史里，`partial`（有来源失败、结果
不全）与正常完成只有色相差别。这既是可访问性问题也是诚实性问题。现在状态词进了行内，
状态点用**形状**编码——实心／半填充带环／方块／空心，去掉颜色仍可分辨。

**句子之间的分隔符是随语言变的。** 给提示补第二句时用 ASCII 空格拼接，两个测试立刻
失败。中文句子之间不该有空格，英文需要。改成两个元素、间距交给样式。

## 已知缺口

> 本节列出的缺口大部分已在[第二轮](PHASE-PARITY-2.md)清掉，
> 那份文档的「已知缺口」是更新的一份。

**阅读面还有 11 项未做**（当时只指派了不需要新字符串的 4 项）：会话管理（新建／切换／
删除对话）、条目面板的翻译状态、未配置模型时的说明与入口、"论文已就绪"的常驻状态、
空对话的起始问题、流式生成的停止按钮、翻译进度的三段式步骤、失败后的重试与"查看原文"、
错误横幅、章节命名不一致（桌面「问 Pharos」vs 网页「AI 对话」）、PDF 页数。

**每日论文的数据目录（Daily Vault）整个没有**。它同时承载研究方向配置与解读结果的
备份／迁移，桌面版目前无处存放。

**两处已知但未修：** `pharosDaily.xhtml` 仍带着 `<browser>` 里无效的 `persist` 属性；
`_renderRail()` 每次渲染都重建，扫描期间会让获得焦点的日期行丢焦点——与详情面板同一个
机制，不在本轮发现清单内。

**网页版仍没有测试运行器。** 只有 `tsc -b` 和生产构建两道关卡，一个纯函数因此错了很久。

**Zotero 8.0.5 基线对齐**是独立议题，见
[CLIENT_DATA_ARCHITECTURE.md](CLIENT_DATA_ARCHITECTURE.md)：客户端源码 schema 129，
在售 Zotero 是 123。它阻塞的是将来的共享文库方向，不影响当前隔离库的使用。
