## 数据目录：最后一个整块缺失的模块

网页版从每日文摘上线就有，桌面版一行代码没有。

**桌面版反而更小。** 浏览器那套脚手架全部不需要移植：目录选择器的授权流程、IndexedDB
句柄存储、权限重新授予、不支持时的降级路径。`FilePicker`、`IOUtils`、`nsICryptoHash`
把这些全替掉了。

### 它备份的到底是什么

这一条比实现本身更要紧，因为桌面版**已经有一个真实的本地文库**，所以答案和网页版不同：

- **已导入的论文不在风险里**——Zotero 条目、PDF、溯源笔记都在本地磁盘上
- **真正没有任何本地副本的是研究方向配置**：分类、每日上限、每个方向及其关键词和顺序，
  全都在偏好设置里编辑后直接写服务器。换服务器或丢账号就得全部手打重录
- 其次是**没有导入的那些论文的解读**，而那是一天文摘里的绝大多数

所以界面上的说法是**「备份的是文摘，不是你的文库」**。一个以为这是文库备份、直到硬盘坏
了才发现不是的用户，就是这段文案要防的失败。

### 两条静默失败的属性，被中断时一个测试都没有

写完时 agent 被 503 打断。工作区是自洽的（构建通过、语言文件同步、145 个测试通过），
但**数据目录没有任何测试**——而它是这个客户端唯一会往用户选定目录里写东西的部分。补上：

**manifest 必须最后写。** 在它指向那些文件之前，新内容只是没人引用的字节，读到的仍是
上一份快照。这条**没法靠断言最终状态验证**——manifest 先写的实现最终看起来一模一样。
所以测试盯的是写入发生的顺序；另一条测试在内容写完、manifest 未写时杀掉进程，确认旧快照
仍然可读。

**manifest 里的路径全部是不可信输入。** 一个数据目录可以被编辑、被同步、被别人递过来。
十个拒绝用例，其中两个是只查 `..` 的守卫会漏掉的：**绝对路径根本不需要 `..`**，
以及**反斜杠在 Windows 上是分隔符**、而在按 `/` 拆分的组件检查里只是普通字符。

## 一个功能缺失 vs 一个正确性问题

其余四项里，三项是缺功能，一项不是。

**`pdf_translation` 账号开关被完全无视。** 全客户端唯一读到这个字段的地方，是管理后台
**给别人设置**。所以在网页版关掉整篇翻译的用户，打开桌面版照样看到译文/对照按钮和翻译
菜单——**同一个账号，两个相反的答案，等于告诉用户他自己的设置没生效**。

缺省方向是刻意的：**值缺失时解析为「开启」**。这个 pref 只在登录或校验看到账号之后才写，
所以"未设置"意味着"还没问过"；反过来默认会让每个账号在启动到首次校验之间都看不到自己
本来拥有的功能。网页版出于同样理由做同样处理。

其余三项：翻译状态列（`getState()` 本来就是同步的，正好是 `dataProvider` 的契约）、
PDF 页数（按附件记忆化，两个界面都在每次选中变化时渲染）、账号显示名。

**翻译状态列对「未知」不显示任何文字**，这是设计不是遗漏。「本地无译文」是几乎每一行的
静息状态，全打上去会把一个可扫视的列变成一面重复的墙，同时让"在另一台机器上翻译过的
论文"和"一本书"长得一模一样。那个区别是详情栏的职责——那里有空间写一句话。

## 网页版才是落后的那一方

复查列出九处，最要紧的是一个真 bug。

**扫描进度整个过程显示 0。** `run.fetched` / `read_done` 在运行开始时被清零，只在
`_finish_run` 里写入真值。所以进度行在可能长达几分钟的扫描期间一直是「已抓取 0 篇 ·
已解读 0」，等工作结束才跳到最终数字。**进度指示器唯一必须准确的时刻，恰恰是它错的时刻。**

我让 agent 在改后端和改前端之间二选一并说明另一个为什么更差。它选了前端，理由比我预设的
硬：**抓取阶段在 `_store_fetched` 之前什么都不提交**，是整批一次性写入，所以就算把 run
行的计数改成增量，「已抓取」在耗时最长的那半段照样是 0——只修好便宜的一半。

而且它顺带发现原来的数字**错了两次**：`run.fetched` 是**共享扫描**的总数（所有账号分类
的并集），而这个界面是按用户的。旧的那行不只显示 0，显示的还是**别人的论文数**。现在改成
从调用者自己的按天汇总取，措辞也从「已抓取」改成「已匹配」。

另外三处：每日论文的卡片和日期行都是裸 `<div onClick>`，**整个右侧详情面板和除最新一天
之外的所有日期都无法用键盘到达**；文摘被关闭这个状态网页版根本不知道，会显示"没有匹配你
方向的论文"，把用户送去改一组工作正常的方向——而且那个按钮通向的设置页**当时根本没有开关**；
以及模型名从不显示。

## 有代价的判断

**跨语言文件一致性的检查搬出了测试套件。** 它一度是空转的——模板字符串两个分支都是空串，
两次读同一个文件，断言恒真。修的过程也不顺：`Zotero.resourcesDir` 指向的不是那个目录；
chrome 注册表解析失败，因为 Fluent 走 L10nRegistry 而不是 `chrome://`。最后的判断是
**检查有价值，但应用的测试环境是错的地方**，改成 `test/check-locale-parity.js`。

留在套件里的是另一半:**运行时拼接的字符串**从枚举自动推导，后端新增枚举值自动覆盖。

**一个测试我写错了名字。** 给日期栏焦点修复加的第二个测试写的是"没变化时不重建"，和第一个
重复，根本没验证签名覆盖了 pending 计数。重写后做了变异检查：把 `pending` 从签名里去掉，
**恰好一个测试失败**——这才确认它不是空转。

**签名跳过重建这个优化有隐藏代价**：签名少覆盖一个输入，界面会一直显示旧数字**而且看起来
完全正常**。所以这类优化必须配一个会因遗漏而失败的测试。

**我自己踩了 BRANDING.md 的第一条。** 在偏好设置里写了一个含 `--` 的 XML 注释。文档停止
解析，七个测试在 hook 里超时，唯一线索是 `customElements.js` 抛的 `not well-formed XML`，
没有文件也没有行号。修完后我扫了全部 `.xhtml` 而不只是我弄坏的那个。
